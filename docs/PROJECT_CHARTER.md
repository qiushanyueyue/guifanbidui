# 项目纲领

## 使命

帮助建筑、市政、结构等工程人员快速识别设计文本中的规范引用，明确判断规范当前是否可用，核对版本、修订与替代关系，并给出可追溯的修改建议；系统应完成规范查新本身，发布机构原文用于正式引用与复核。

## 服务对象与核心结果

- 设计、审图、咨询和工程管理人员：减少过期、废止、编号类型错误和漏写修订版。
- 自动化调用方（如 WorkBuddy）：仅凭规范名称和编号取得结构化、可解释的只读结论。
- 维护者：能追踪每条结论的来源、时间、核验级别、冲突和失败原因。

成功结果必须同时具备：输入容错、明确业务结论、证据可追溯、隐私可控、界面可用和结果可复验；正常规范明确判断率目标不低于 95%。

## 核心原则

1. **明确判断优先**：尽最大可能输出“现行 / 现行但需采用最新修订 / 已废止 / 已被替代”；只有真实异常才使用 `unknown/conflict`，前端统一表达为“暂无法确认”。
2. **新鲜缓存优先**：查询顺序为数据库新鲜缓存 → 权威官方源 → 工标网/搜建筑精确匹配（双源一致时升级为交叉核验）→ 历史数据库 → 用户反馈；缓存过期或本地漏收时自动进行有界联网复核。
3. **来源可追溯**：身份、状态、版次、替代关系与来源证据分层保存。
4. **本地优先提取**：先用确定性规则处理空格、括号、OCR、版次和连续条目；远程模型只是零结果兜底。
5. **时间有效性**：所有生产数量、部署和核验结论必须带 `as_of` 与证据，新证据使旧事实失效但不抹除历史。
6. **真实流程验收**：测试、构建、接口和浏览器流程分别验证，不互相替代。
7. **最小安全变更**：保护用户脏工作树、生产数据和 Secret，不做无关重构。

## 范围

- 规范名称/编号/版次提取与标准化。
- 当前状态、修订、替代、来源和核验级别查询。
- 搜建筑、工标网及可配置官方来源的证据同步和质量门禁。
- Excel 候选清洗、隔离、导入和审计。
- Web 查询、问题筛选、来源跳转和审查结果导出。
- `/api/v1/verify` 等自动查新入口；仅查询规范名称和编号，过期元数据可触发受限联网复核并写回来源证据缓存。

## 非目标

- 不提供规范全文、付费内容复制或版权受限资料分发。
- 不把第三方网站结果包装成官方认证。
- 不在普通查询中进行无界爬虫、数据库重建或生产迁移；过期单条记录的有界联网复核属于核心查询流程。
- 不让大模型直接决定“现行/废止”；模型只辅助提取，最终状态来自数据库证据与解析规则。
- 不接收 WorkBuddy 上传的图纸、完整设计说明或内部项目资料。

## 数据来源与判定规则

- 权威官方来源明确确认时直接作为最终结论并标记 `official`，第三方差异保留为后台证据但不降级官方结论。
- 官方源暂无机器可用数据时，工标网或搜建筑任一来源对编号、名称给出完整匹配且明确显示状态，可输出明确状态并标记 `single_source`；两站对身份、状态及替代关系一致时升级为 `cross_verified`。
- 引用一致性与规范状态分开判定：单一来源记录的编号、名称完整匹配即可显示“完全一致”；状态字段缺失时仅规范状态显示“暂无法确认”，不得把引用匹配降成“待核验”。
- 只有来源真正冲突、全部来源不可用、规范无法检索或替代关系矛盾时使用 `unknown/conflict`，前端显示“暂无法确认”；单纯存在来源链接不算完成核验。
- 新鲜期默认 30 天，可用 `STANDARD_CACHE_FRESH_DAYS` 调整；生产持久数据库默认启用过期自动复核，可用 `ENABLE_LIVE_STANDARD_REFRESH` 显式控制。
- Excel 目录是候选/补充证据，不是运行时兜底；未经外部核验的记录保持 `unverified/unknown`。
- 规范状态与引用版本必须分开表达；现行规范存在版次或局部修订时，应输出“现行，需采用……”并生成包含最新版次/修订的推荐引用。

## 隐私与安全

- 默认所有输入在本地解析；只有本地零结果且管理员显式开启时，才可把该段文本发送到服务端配置的远程模型。
- 远程兜底开启时必须在用户说明和项目记忆中保留这一边界，不能宣称“所有文档永不外传”。
- Secret 只允许存放在平台服务端 Secret；不得写入前端环境变量、代码、记忆、提交和日志。
- 生产数据库迁移、批量导入、部署和外部集成必须有明确授权、质量门禁、验证与回滚意识。

## 可靠性与降级

- 缺少生产 `DATABASE_URL` 时服务必须明确 degraded，不用临时数据库冒充生产持久化。
- 来源结构变化、超时和解析失败应记录失败并继续提供历史数据库的明确结论；历史也不足时才显示“暂无法确认”。
- 输出必须包含核验级别、最近核验时间和可用来源；无来源的现行结论不允许发布。

## 完成定义

一次耐久变更只有在以下条件全部满足时才完成：

1. 需求逐项实现且没有扩大范围。
2. 目标测试、全量测试、lint/build 和相关真实用户流程已实际运行。
3. 数据或部署变更经过只读复查，结果区分本地、预览、生产和未验证。
4. Secret 扫描、脏工作树保护和失败/回滚边界已检查。
5. `CURRENT.md`、`HISTORY.md`、必要 ADR 与根 `MEMORY.md` 已按耐久程度更新。
6. `python scripts/check_project_memory.py` 与 `git diff --check` 通过。
7. 交付报告说明改动、验证和剩余风险。
