# 项目记忆使用说明

## 分层结构

| 层 | 文件 | 更新方式 | 用途 |
| --- | --- | --- | --- |
| 自动入口 | `../../AGENTS.md` | 规则变化时更新 | 强制新对话读取与收尾协议 |
| 稳定纲领 | `../PROJECT_CHARTER.md` | 低频、需说明原因 | 使命、边界、不变量 |
| 紧凑索引 | `../../MEMORY.md` | 耐久变化时刷新 | 快速定位当前事实和风险 |
| 当前事实 | `CURRENT.md` | 原位更新 | 最新已验证运行状态 |
| 历史事件 | `HISTORY.md` | 只追加 | 事实演变、失效与验收记录 |
| 长期决定 | `decisions/` | ADR只追加/标失效 | 为什么这样做及替代方案 |

文件系统记忆是本仓库的默认方案。只有当规模增长到关键词检索无法可靠找到事实、出现大量实体关系或需要跨项目语义检索时，才评估向量库或时态知识图谱。

## 新对话读取策略

始终先读纲领、根记忆和当前事实；ADR 与历史按任务关键词即时读取，不把所有历史塞进上下文。生产事实必须实时复核后才可对用户宣称“当前”。

## 更新判定

需要记忆：架构/API/状态语义、数据/来源/部署、生产数量、验证基线、隐私边界、长期风险与决策发生变化。

通常不需要记忆：纯格式、注释、一次性诊断、临时文件和未形成结论的实验。仍应在任务收尾中说明为何无需更新。

## 事实模板

```markdown
### 事实名称

- value: ...
- as_of: YYYY-MM-DDTHH:MM:SSZ
- verification: production_verified | tested | implemented | unverified
- evidence: 命令、API、测试或仓库文件
- supersedes: 可选，旧条目或旧事实
- notes: 风险与适用范围
```

会变化的事实缺少 `as_of`、`verification` 或 `evidence` 时，不应写入当前事实。

## 冲突、失效与合并

- 采用较新的已验证证据作为 `CURRENT.md` 当前值。
- 在 `HISTORY.md` 追加“旧事实被何证据取代”，不删除旧记录。
- 长期决定被替代时，新建 ADR，并把旧 ADR 状态改为 `superseded by ADR-xxxx`。
- 根 `MEMORY.md` 只保留高价值摘要和索引，避免无限增长。

## 隐私与保留

禁止存储 Secret、数据库连接串、恢复码、Cookie、个人账号数据、完整用户文档和大段日志。历史记录只保存完成结果、关键证据与风险，不保存认证过程。
