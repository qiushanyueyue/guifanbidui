# ADR-0007：发布质量门必须在提交前生效

- status: `accepted`
- date: `2026-10-31`
- owners: 项目维护者与代码代理
- refines: [`ADR-0004`](ADR-0004-sync-health-and-ci.md) 的批次质量门

## 背景

`rebuild_v2.py` 原先由 `publish_staging` 先提交，再校验替代关系。校验失败时工作流变红，但数据已经发布。每日、每周、每月任务因此长期失败，同时生产数据继续变化，质量门实际不起拦截作用。报告也只有数量，定位异常关系需要访问数据库。

## 决定

- 重建发布是一个事务：`publish_staging(commit=False)` 只 flush，校验通过才提交，不通过则整体回滚，退出码仍为 2。`--retry-quarantine` 的隔离重试并入同一事务。
- 报告增加 `publication`（`committed` / `rolled_back`）和 `relation_issues`，列出异常关系的编号与原始关系文本。
- 已暂存的来源证据不回滚，问题解决后下一次发布会使用。查询时联网复核写入 V2 的路径不经过此门，语义不变。

## 替代方案

- 保持先提交后校验：工作流状态与数据不一致，不采用。
- 只隔离异常关系、其余照常发布：批次可持续发布，但会让门禁变成告警，需要单独决定隔离语义，本次不采用。

## 后果

- 只要仍有异常关系，定时发布会被完全阻塞，定时核验取得的新证据只暂存、不进入公开数据，直到异常关系被修复。
- 部署后第一次失败的任务日志会列出当前异常关系。

## 复核条件

- 如果异常关系经常阻塞发布，重新评估“隔离单条关系、其余继续发布”。
