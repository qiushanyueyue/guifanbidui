# ADR-0003：明确结论与新鲜期自动查新

- status: `accepted`
- date: `2026-09-01`
- owners: 项目维护者与代码代理
- supersedes: [`ADR-0002`](ADR-0002-third-party-status-evidence.md) 中普通查询数据库-only及正常记录保守展示 unknown 的部分

## 背景

项目第一核心价值是替设计人员完成规范查新。大量正常规范显示“待核验”会把判断责任重新推给用户，也无法满足正常规范明确判断率不低于 95% 的目标。与此同时，规范状态、引用版次、局部修订和来源可信度属于不同维度，不能混成一个保守标签。

## 决定

主查询采用：数据库新鲜缓存 → 权威官方源 → 工标网/搜建筑精确匹配（双源一致时升级交叉核验）→ 历史数据库 → 用户反馈兜底。

- 默认新鲜期为 30 天，可配置；生产持久数据库中的过期或异常记录在 `/api/v1/verify` 查询时进行有界联网复核。
- 官方来源对匹配身份给出明确状态时直接定案为 `official`。
- 官方源不可用时，工标网或搜建筑任一来源对编号、名称完整匹配并明确显示状态，即可形成明确业务状态并标记 `single_source`；两站对编号、名称、状态及替代关系一致时升级为 `cross_verified`。
- 引用一致性与规范状态是两个维度：任一来源记录的编号、名称完整匹配即显示“完全一致”；该来源没有明确状态时，仅状态栏显示“暂无法确认”。
- 本地库未收录不再立即结束；`/api/v1/verify` 对单条输入执行有界来源发现，成功后写入缓存。编号的强制性/推荐性标识不同（例如 `GB` 与 `GB/T`）时返回可操作的编号属性修正，不冒充完全一致。
- 在线复核成功后追加来源证据并刷新缓存；在线失败时保留已有历史明确结论。
- 只有来源冲突、全部不可用、无法检索或替代关系矛盾时返回 `unknown/conflict`，用户界面统一显示“暂无法确认”。
- 规范状态与引用版本分开输出；现行规范存在版次或局部修订时生成“现行，需采用……”以及完整推荐引用。
- 用户反馈继续保留，但仅作为自动查新失败后的纠错通道。

## 替代方案

- 所有查询数据库-only：响应稳定但会长期保留过期或 unknown，无法完成查新核心任务，不采用。
- 单个第三方来源不加身份和明确状态门槛即批量定案：误匹配风险不可控，不采用。
- 任何来源差异都降级官方结论：会让低优先级来源否定权威证据，不采用。

## 后果

正常记录会优先得到明确业务结论，修订版引用可直接用于改正设计说明。代价是过期查询可能增加外部请求延迟，需继续通过限速、超时、失败回退、来源证据和定时同步控制运行风险。

## 复核条件

当明确判断率低于 95%、在线复核延迟不可接受、来源条款或访问方式变化、官方适配器覆盖显著提升，或第三方交叉误判率不可接受时复核本决定。
