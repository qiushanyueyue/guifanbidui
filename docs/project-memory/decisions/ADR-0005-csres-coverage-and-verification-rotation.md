# ADR-0005：CSRES 主覆盖与存量核验轮转

- status: `accepted`
- date: `2026-10-03`
- owners: 项目维护者与代码代理
- complements: [ADR-0003](ADR-0003-decisive-freshness-aware-verification.md)、[ADR-0004](ADR-0004-sync-health-and-ci.md)

## 背景

用户明确要求保留工标网作为可信、覆盖较全的主要来源。公开直连复现证明，常用规范搜索和详情可正常返回，正常零结果页却被旧解析器误报 ParseError。中文 keyword 被 requests 按 UTF-8 编码、被 CSRES 按 GBK 解码，会产生乱码。此外，日/周 unknown-only 每次从候选队列开头开始，长期无命中的记录会阻塞后续候选。证据见 [公开来源抽查](../../../artifacts/csres_source_probe_20261003.json)。

## 决定

- CSRES 承担主要规范覆盖、明确状态及版次/日期/替代元数据核验；编号与名称匹配且有明确状态时允许 single_source 明确结论，不因第三方身份一概降为 unknown。
- 搜建筑补充规范身份、资料入口与第二来源证据。页面存在不等于现行；有明确状态时仍按 ADR-0003 处理。
- 官方公告补充权威发布、修订、实施、废止及强条变更事件；明确且适用的官方证据优先，保留第三方观察。本轮只确定分工，不宣称官方适配器已连通。
- “覆盖较全”是主来源选择依据，整体命中率仍需按目标规范集量化；7项抽样不能证明全库覆盖或更新及时性。
- 查询参数采用 gb18030 字节，由 requests 一次百分号编码；响应解码与查询编码是两个独立问题，不因本次问题更改所有来源的响应解码。
- 搜索页所有列按表头映射；缺状态不猜现行，缺日期/发布部门不取相邻列。异常结构、限流/验证页与明确零结果分开处理。
- 明确零结果要求正常 CSRES 查询标题及零结果提示；未知结构仍报错。未命中仍计批次失败，不降低既有来源健康与关系质量门。
- 详情身份与搜索实际命中编号核对；GB↔GB/T 同序号同年份演进仍允许，另一编号详情不得覆盖搜索证据。
- 条文废止通知可能用分号串联多个触发规范；必须先移除完整“自……实施之日起……强制性……废止”通知，再解析整本替代，保留通知之外的真实替代关系。三条公开源原文及V2发布回归证明此边界。
- 日/周 unknown-only 使用排序后的编号稳定游标和独立 `csres / verify_v2_unknown` checkpoint；失败也前进，到末尾循环。月度保留独立 `csres / verify_v2` 进度；显式编号核验不修改两个游标。
- 发布重放不能刷新 `last_verified_at`：按实际明确状态来源的观察时间计算；官方只取官方证据，交叉核验取两源各自最新观察中的较早时间。仅成功重新抓取/在线核验刷新观察时间，失败与未命中保留旧结论和旧时间。重复抓取相同内容允许更新其最新观察时间，并同步 V2 来源表；状态选择按实际观察时间而非首次插入 ID。
- 存量复核与新规范发现是不同流程。未来新规范发现应从可枚举列表/公告进入 V2 暂存与核验，不靠重复查询已知编号实现；本轮未接入新列表或官方公告。

## 替代方案

- 因非官方而停用 CSRES：损失覆盖且违背用户已接受的单源明确判定，不采用。
- 找不到表格一律返回空：掩盖改版与异常，不采用。
- 用大模型补全无命中记录的状态：没有来源依据，不采用。
- 每次固定检查队首：会饥饿；可变列表的数组偏移也会因已解决记录消失而跳过候选，改用编号游标。

## 后果

来源错误可以定位，已有覆盖来源继续发挥作用，长期未命中不再阻塞其余 unknown。正常未找到仍可能使批次质量门失败；这是覆盖不足的真实信号。生产三条错误关系已定位为跨分号条文通知误解析；修复parser，派生边随常规发布重建。本轮只读核验，不手工删边，不放宽质量门。

## 复核条件

CSRES 请求编码/结构变化、目标集覆盖或更新延迟不达标、官方事件开始稳定接入、并发任务增多或复核队列需要更细优先级时复核。
