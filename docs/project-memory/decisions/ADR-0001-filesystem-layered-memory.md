# ADR-0001：采用仓库内分层文件记忆

- status: `accepted`
- date: `2026-08-25`
- owners: 项目维护者与代码代理

## 背景

项目需要让新对话快速恢复使命、当前生产状态、历史决定和风险，同时让人类能审查、回滚并随代码版本同步。当前规模是单仓库、少量长期实体，主要问题是文档冲突和新对话遗漏，而不是语义检索能力不足。

## 决定

使用 Git 管理的分层文件系统：`AGENTS.md` 自动入口、稳定纲领、紧凑根记忆、当前事实、只追加历史和 ADR。通过标准库脚本检查结构、链接与明显敏感信息。

当前不引入向量数据库、Mem0、Graphiti、Cognee 或外部记忆服务。

## 替代方案

- 单一超长 `MEMORY.md`：简单，但容易无限增长、冲突和上下文污染，未采用。
- 向量库/Mem0：适合多租户和大规模语义检索；当前增加运行成本和隐私面，未采用。
- Graphiti/Cognee 时态图：适合复杂实体关系和多跳查询；当前工程收益不足，未采用。
- 只依赖聊天平台记忆：不可随仓库审查和版本化，且不同代理不可共享，未采用。

## 后果

优点：透明、零外部依赖、与提交同行、易审查，任何代理都可用基本文件工具读取。代价：需要人工遵守更新协议，关键词/链接检索能力有限；因此把记忆更新纳入完成定义并提供检查器。

## 复核条件

出现以下任一情况时重新评估：记忆文件超过人工可维护规模；关键词检索频繁漏召回；需要跨多个仓库共享实体；需要按有效时间进行复杂关系查询；或自动评测证明文件检索明显不足。
